# Main-table input and scoring contract

This page describes the retained historical profiles. `--protocol public-vsi-v1` adds a separate [public VSI input route](PUBLIC_VSI.md) for Base and the two QUASAR roles. It preserves manuscript scores as references and records new measured scores separately. Historical loader/log gaps do not prevent using this new protocol; semantic reference availability is checked from its generated evidence.

The five local roles are `base`, `visual_sft` (W06/46592), `visual_grpo` (W05/2048), `quasar_sft` (W02/44544) and `quasar_grpo` (W01/2048). Every trained role uses the same fixed official Qwen3-VL-8B-Instruct backbone revision. `configs/table12_profiles.json` binds model identities, generation recipes, original unrounded scores and per-cell blockers. `configs/table12_sources.json` binds official QA revisions, full ordered membership, frames and fixed smoke examples.

## Original inputs

| Table | QA | Video/geometry route | Answering reference |
| --- | --- | --- | --- |
| 1 / VSTI | Historical 6,042, five-task score | 312 original videos; recorded 32-frame sequence; QUASAR uses CUT3R over that sequence | Historical target-camera rule for every row: last matching `frame N of 32`; final frame when no match |
| 2 / VSI trained models | Original 5,130, eight-task score | 288 original videos; registered extraction bank; QUASAR runs CUT3R over the full candidate sequence, then selects 32 evenly spaced indices with `torch.linspace(...).round()` | Scene-center reference for nonsemantic tasks; semantic question viewpoints remain blocked |
| 2 / Base | Historical M01 5,130 | Original raw-video loader and exact frame settings unavailable | No spatial module; input protocol remains unresolved |

`data/manifests/table12_*_frames.jsonl` provides the original export sequence, full geometry sequence and final model sequence. The first two are not interchangeable. Video frame count, order and paths are checked before model execution. Explicit frame membership is public metadata; no computed features or geometry are packaged.

For Visual-only, the registered final 32 RGB images are sufficient. For QUASAR, the camera poses and point maps are regenerated by the pinned CUT3R code/weight. The supplied preparation code constructs references in that same scene coordinate system. Correct answers and evaluation object targets are not used. Native ScanNet depth is a separate training/input route and does not replace CUT3R in these main tables.

VSI trained-model options reproduce the original four-option conversion, including 671 expanded option lists. Base M01 retains its own original options and has no new generation entry. VSTI's 5,736-question correction, 5,598 parser subset and nine-subtype aggregate are separate experiments.

## Model input and scoring

Official questions are converted to answer-free generation rows with only answer format, options and units. Correct answers remain in separate scoring records. Generation processes receive the answer-free file. References contain only the declared observation/reference information; training targets are not required.

The recorded trained-model arguments specify 32 frames, 50,176 pixels per frame, bf16 model parameters, seed 0, temperature 0 and top-p 1. Token limits remain role/dataset-specific: Visual-only SFT 24, Visual-only GRPO 24 on VSI and 20 on VSTI, QUASAR 16. Base VSTI uses its own original prompt/generation code, sdpa attention and 24 tokens, with a raw-RGB versus newly cached-feature acceptance comparison before generation.

The existing scorer computes numeric MRA and choice accuracy, then a five-task VSTI or eight-task VSI macro-average. TSV columns follow the paper's task order. Differences use unrounded archived references. Smoke-sample scores are not entered as table scores. `experiments/main/*/*.predictions.jsonl` contains the historical answers; the reviewer does not read them.

## Resume and failure behavior

A run freezes the paths, source versions, selected model profiles and complete generation recipes. Run files record the run-contract identifier `quasar-release-candidate-v43-20261009-r1` from `quasar.reviewer`; it names the input and run contract, which is unchanged in this release, so existing runs remain resumable. The same command resumes an ordered, unique prefix of complete answers. Duplicates, out-of-order answers, unknown IDs, failed records and missing final answers are errors. An interrupted final JSONL line requires preserving and repairing that line before resuming. Logs retain each attempt's exact command and exit code.

Newly computed preparation stays within `run_root`; one process may write each run. Changed settings require a different run directory. A known blocked cell returns `BLOCKED_INPUT`; other cells continue. Exit 2 means at least one such blocked cell, not a complete two-table reproduction.

## Known input gaps

Fixed-sample validation covers two VSTI questions (the first numbered-target example and the first historical parser-mismatch example) for all five roles, and three VSI questions covering ARKitScenes, ScanNet++ and ScanNet for the four trained roles. The resulting 22 answers exercise preparation, model execution and scoring. Five new frame sequences match their retained historical pixels exactly; their regenerated geometry and references match under `configs/table12_validation_rules.json`. Base VSTI also passes exact raw-RGB/cached-feature token comparison. These checks establish the fixed input routes, not full-dataset numerical reproduction.

Base VSI lacks the authoritative historical video loader, model revision and sampling/decoding details. QUASAR VSI lacks the transform between 1,162 semantic question viewpoints and regenerated CUT3R coordinates. These three full cells remain blocked. Canonical-reference smoke examples on VSI do not resolve the semantic gap. The separate historical training-object generation gap does not block downloaded-weight evaluation.

An independent run completed all five VSTI cells and the two Visual-only VSI cells; see [reproduction results](REPRODUCTION_RESULTS.md).
